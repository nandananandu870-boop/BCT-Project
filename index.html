How it works

1

SHA-256 Hashing

Your file is read as raw bytes and passed through the browser's native Web Crypto API. The resulting 256-bit digest uniquely fingerprints the file — any byte change produces a completely different hash.

2

Block Construction

A block is built containing the document hash, the previous block's hash, a timestamp, owner metadata, and an index. This is then hashed again to produce the unique block hash — chaining them immutably.

3

Chain Integrity

Each block's prevHash points to the prior block's hash. Tampering with any block breaks every subsequent link — the chain becomes verifiably corrupt. Exported JSON can be re-validated offline.

4

Verification

To verify, re-upload the original file. Its SHA-256 is recomputed client-side and compared against every block in the chain. A match proves the document existed, unchanged, at registration time.

ChainProof — All computation is client-side. No file data leaves your browser.
